## 状态与历史

`outbound_deliveries` 是发送记录来源，每段使用稳定记录 ID 和 batch/segment 索引。

| 状态 | 含义 | 进入真实模型历史 |
| --- | --- | --- |
| candidate | 已生成/准备，尚未提交；失效的未提交段也保留在此 | 否 |
| pending | 发送调用正在进行，尚无结果 | 否 |
| simulated | Dry Run，绝未调用真实发送 | 否；只在模拟模式中使用模拟历史 |
| sent | 平台返回成功回执，不代表对方已读 | 是，仅写入一次 |
| failed | 明确失败；人工记录可重试或复制 | 否 |
| unknown | 超时、断线、无回执或重启遗留 pending，无法判断是否已送达 | 否；先核对实际 QQ，禁止盲目自动重发 |

`messages.history_kind` 区分 real / simulated / legacy_unknown。
Console/Mock 模拟聊天仍有上下文；真实 QQ 模式不使用模拟回复和未知旧 assistant。
重试复用原发送记录；已确认段不重新发、不重复写历史或触发记忆。
后台模型错误只在本地会话显示，不发送给 QQ 联系人。

## 配置及启用

- 运行开关以 Runtime 为准；变更成功后回传界面。保存启动默认值不会改变当前开关。
- 模型和 OneBot 连接参数：保存后手动点“重新连接”；数据库路径变化需重启整个程序。
- QQ_WS_TOKEN 是 OneBot WebSocket 的 Bearer 认证；QQ_WEBUI_TOKEN 是 WebUI 登录，互不替代。
- 新代码需用户自行重启才会加载；本次没有重启、修改开关或改变现用配置。
- 关闭开关只阻止尚未提交的动作，不能承诺撤回已经提交平台的段落。

## 账号键与保守迁移

内部：`scope:qq:10001:qq:private:20002`；发送目标仍为 `qq:private:20002`。
`account_profiles` 使用 `qq:10001`；`conversation_controls` 使用内部会话键。
原 `current_account_profile` 保留为旧数据，不默认复制到任何 QQ 账号。
需要在确认账号后使用本地 `/account set ...` 明确配置当前账号资料。
登录和历史同步也不再自动删除旧的 `qq:private:<当前账号>` 记录；该旧路由可能
是另一个账号与此人的正常私聊。自己的目标只在当前目录/发送入口过滤，不猜测
旧数据归属后删除。

迁移工具**不在启动时自动执行**。应用仅增加兼容字段/新表；历史归属只在显式
选定的数据库副本上处理。本次未对现用库执行任何初始化或迁移。

先自行创建一致的 SQLite 备份（运行中不要直接复制可能变化的 DB/WAL 文件）。
人工确认副本后才运行，例如 CMD：

```bat
.venv\Scripts\python.exe -m app.tools.migrate_accounts --database-copy artifacts\reviewed_copy.db
.venv\Scripts\python.exe -m app.tools.migrate_accounts --database-copy artifacts\reviewed_copy.db --source-links artifacts\reviewed_source_links.json
```

`--source-links` 可选，内容为人工核验的“messages 行 ID → inbound_platform_messages
行 ID”JSON 对象，例如 `{"12": 34}`。禁止用文本相同、昵称、当前只登录了一个账号
等条件猜测对应关系。工具拒绝默认正式库 `data/chatbot.db`；若正式库另设路径，
操作者仍须确保传入的确实是副本，不应把工具拒绝默认路径当成所有正式库的防护。

来源事件的路由、正文、发送者角色及账号必须匹配。摘要/记忆的全部来源、前序摘要、
替代记忆和候选目标都确认属于同账号才迁移。保留消息和派生记录的原 ID、来源范围、
supersedes/previous 关系；重复执行安全，不删除原记录。
无法证明归属的记录和旧手工画像保留在原命名空间，并在 `legacy_assignment` 中
标记 unassigned，不自动注入任何新账号。全新 QQ 会话不会读取不明归属的旧资料。
